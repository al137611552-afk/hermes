# CI 打包用的版本约束（`pip install -c build-constraints.txt`）。
#
# **为什么只钉这几个**：这里钉的是**决定 exe 能不能启动**的那条原生链——PyInstaller 把它们
# 打进产物，装到哪个版本就固化在包里，出问题时用户端没有任何补救余地。而 anthropic/openai/mcp
# 这类纯 Python SDK 故意**不钉**：它们是运行时对外说话的部分，跟上游走对用户有利，
# 且出问题时改配置/换模型就能绕开。钉住一切会让每次安全更新都变成一次改仓库。
#
# **版本从哪来**：2026-08-14 的 run #10 —— 这套组合真打出过包、真在 Windows 上跑起来过
# （踩了 Mark of the Web 之后解除锁定即正常，与依赖版本无关）。
#
# **升级流程**：改这里的版本 → 推 tag 出包 → **在 Windows 真机上跑起来确认** → 才算数。
# 别在这里图省事写范围号：范围号等于没钉，产物又会随打包时间漂移。
