# 验证用例 — 站外协同：进程退出通知 + 条件等待器（v3.70.0 / ADR 0026 W1）

> 对应包：`hermes-dev-3.70.0-win64.zip`（或源码装）。
>
> **这个功能没有 GUI 依赖**，后端已在 Linux 上真模型真跑 6/6（`scripts/diag_offsite_realrun.py`）。
> **这里要验的是我验不到的三层**：① Windows/PowerShell 下的行为；② 真 GitHub CI（我只验过本地进程）；
> ③ **会话空闲时被自动起一轮**在 WebView2 里的观感（消息怎么落、状态怎么变）。
>
> 每条填「实际结果」+ ✅/❌。有 ❌ 把现象/截图发回，**别自己改到通过**。

**这一版新增了什么**：模型可以「起一件事 → 这一轮就结束 → 等它完成时自己醒来接着干」。两种形态：

| 参数 | 用途 |
|---|---|
| `notify_on_exit`（配 `background:true`） | **本地长跑进程**退出即通知——调别的 agent / 构建 / 测试 |
| `wait_until_success`（+ `poll_seconds` / `timeout_minutes`） | **站外条件**：周期重跑判据命令直到 exit 0——CI、云端任务 |

**关键不是"能通知"，是"醒来时还记得当初在等什么"**。TC-2 专门验这条。

## TC-3 等真 CI（站外条件）

先随便推一个改动触发 CI（或用最近一次的 run），然后对 hermes 说：

> 用 `wait_until_success` 等我仓库最新一次 GitHub Actions 跑完，每 30 秒查一次，最多等 20 分钟。
> 判据命令你自己写，仓库是 `al137611552-afk/hermes`。跑完告诉我结果是绿是红。

判据命令参考（它自己写不出来时可以给它这条）：

```powershell
$r = (curl.exe -s "https://api.github.com/repos/al137611552-afk/hermes/actions/runs?per_page=1" | ConvertFrom-Json).workflow_runs[0]
if ($r.status -eq 'completed') { exit 0 } else { exit 1 }
```

- 预期①：它调工具时带 `wait_until_success: true`，并回一句「已开始等待 #N：每 30s 探测一次…」，
  **这一轮随即结束、会话空闲**。
- 预期②：**等待期间不产生任何模型调用**——看顶栏用量 chip 的 token 数，**等待过程中不该增长**。
  （这正是它跟"让模型自己每轮查一次"的本质差别。）
- 预期③：CI 跑完后自动醒来，报出结论。

## 已知边界（**不是 bug，不用报**）

- **等待期间关掉 app，等待不会续上**——这是刻意的（ADR 0026 决策 4：W2「重开带着答案提醒」暂缓）。
  重开后它不知道你曾在等什么，需要你重新说一次。
- **只在 DeepSeek 上验过模型会不会自发使用**。换别的模型若不选这两个参数，
  属于已知风险（"机制建好了模型不用"），请如实记下来，那要改的是提示词/描述而不是机制。
- 轮询下限 5 秒、时长上限 120 分钟——填更小/更大的值会被夹住，是设计如此。
