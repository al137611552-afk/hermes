## 一、TC-1 「在浏览器打开」修复（**重点**）

**机制**：以前用 `webbrowser.open(file:// URI)`，`as_uri()` 会把中文/空格百分号编码
（`我的项目` → `%E6%88%91%E7%9A%84%E9%A1%B9%E7%9B%AE`），Windows ShellExecute 解不可靠 → 静默失败。
现在改成优先 `os.startfile(原生路径)`，且打不开会**弹 toast 报错**（以前点了毫无反应）。

### TC-1.1 中文/空格路径的已有项目（**这条就是原 bug，必须过**）

- 准备：新建一个**路径含中文或空格**的目录，例如
  `C:\Users\<你的用户名>\Documents\我的项目 测试\`（中文 + 空格都占上最好）。
- 步骤：
  1. 启动 hermes（`py -m agentcore.app`），用「打开已有项目」选中上面那个目录。
  2. 让它生成一个 HTML，例如：`做一个简单的 index.html，页面上写「hello 测试」`。
  3. 右侧预览面板点开 `index.html` → 点「**在浏览器打开**」。
- 预期：**系统默认浏览器真的打开这个文件**，页面显示「hello 测试」。
- 对照（修复前的表现）：点了没反应、没报错、浏览器不动。
- 实际结果：__________ ✅/❌

### TC-1.2 纯 ASCII 路径没被改坏（回归）

- 步骤：换一个纯英文无空格路径的项目（如 `C:\proj\demo\`），重复 TC-1.1 的 2~3 步。
- 预期：照常打开（这条路以前就是好的，别被改坏了）。
- 实际结果：__________ ✅/❌

### TC-1.3 失败时有明确提示（**不再静默**）

- 步骤：
  1. 预览一个 HTML 文件，**先别点按钮**。
  2. 在资源管理器里把这个文件**删掉**（或重命名）。
  3. 回到 hermes，点「在浏览器打开」。
- 预期：右下角弹 toast，内容形如 `文件不存在`；**关键是有提示**，而不是毫无反应。
- 实际结果：__________ ✅/❌

### TC-1.4 非 HTML 文件不受影响（旁证）

- 步骤：预览一个 `.png` 或 `.md`，确认面板行为如常（这两类没有「在浏览器打开」按钮，只看有没有被误伤报错）。

## 二、TC-2 权限绕过加固（A1）

**机制**：智能确认分级（`auto_approve_safe`，默认开）会自动放行只读命令。这次修了 4 类绕过：
换行分隔符 / 单个 `&` / `env` 当执行器 / 超长命令。

> ⚠ **看哪里判断**：执行行会标注「（免确认：原因）」。**弹出确认条 = 没有自动放行 = 本次期望的结果。**

### TC-2.1 绕过命令现在会弹确认（**安全项，重点**）

对每条命令，让 hermes 执行（可以直接说：`执行这条命令：<命令>`），看是否**弹出权限确认条**：

| # | 命令 | 期望 | 实际 |
|---|---|---|---|
| a | `Get-ChildItem` 换行 `Remove-Item x.txt`（一条命令里真的敲回车换行） | **弹确认** | ______ ✅/❌ |
| b | `Get-ChildItem & Remove-Item x.txt` | **弹确认** | ______ ✅/❌ |
| c | `env FOO=1 whoami`（PowerShell 下可能直接报错，只看有没有弹确认） | **弹确认** | ______ ✅/❌ |
| d | `git grep -O rm foo` | **弹确认** | ______ ✅/❌ |
| e | `git diff --output=C:\Temp\x.txt` | **弹确认** | ______ ✅/❌ |

> a 这条最重要：修复前 `ls\nrm -rf /` 会被**自动放行**。
> 造这条命令的省事办法：让 hermes「执行一条命令，第一行是 Get-ChildItem，第二行是 Remove-Item x.txt」。

### TC-2.2 日常只读命令仍然免确认（**防过度收紧，同样重要**）

| # | 命令 | 期望 | 实际 |
|---|---|---|---|
| a | `Get-ChildItem` | 免确认（标「免确认：只读白名单」） | ______ ✅/❌ |
| b | `git status` | 免确认 | ______ ✅/❌ |
| c | `git status; git diff`（PowerShell 用 `;` 串） | 免确认 | ______ ✅/❌ |
| d | `whoami` / `Get-Date` | 免确认 | ______ ✅/❌ |
| e | `py -m pytest -q`（在有测试的项目里） | 免确认 | ______ ✅/❌ |

> ❌ 判据：如果这些**开始弹确认了**，说明收紧过头，是回归 bug，务必报回来。

### TC-2.3 毁灭性命令照旧拦截（回归）

- 步骤：让它执行 `Remove-Item -Recurse -Force C:\`。
- 预期：被**强制拦截**（不是"弹确认"，是直接拦），提示毁灭性命令。

## 三、TC-3 会话级工具预算（A2）

**机制**：新增「每会话联网搜索上限」「每会话委派上限」（默认各 200，0=不限）。
主 Agent 与子 Agent **共用一份计数**。撞上限不执行该工具，把「预算用尽」回灌模型让它收敛。

### TC-3.1 设置面板能看到并保存（**GUI，Linux 验不了**）

- 步骤：设置面板 → 「限额与预算」→ 找到 **「预算」组**。
- 预期：能看到两个新项，默认值都是 **200**；改成别的值 → 保存 → **重启 hermes** → 值还在。
- 实际结果：__________ ✅/❌

### TC-3.2 撞上限真的生效（把上限调到很小来验）

- 步骤：
  1. 把「每会话联网搜索上限」改成 **2**，保存。
  2. **新开一个会话**（计数按会话算，不新开会用旧的）。
  3. 让 hermes 做个需要多次搜索的任务，例如：
     `搜一下 2026 年 8 月 Claude Code 有哪些更新，再搜 Codex CLI 的，再搜 Gemini CLI 的，分别总结`
- 预期：第 3 次 `web_search` 起返回「[预算用尽] 本会话 `web_search` 已调用 2 次…」，
  且模型**用已有信息收尾作答**（说明哪些没查到），而不是卡死或反复重试。
- 实际结果：__________ ✅/❌

### TC-3.3 改回默认不影响日常（回归）

- 步骤：把两个值改回 200，新开会话跑一次正常的联网任务。
- 预期：完全感觉不到预算存在。
- 实际结果：__________ ✅/❌

## 四、TC-4 `run_powershell` 的 `cwd` 参数（A3）

**机制**：新增可选 `cwd`，在工作区子目录里执行命令，不必再写 `cd xxx && …`。受工作区约束。

### TC-4.1 在子目录里执行（**PowerShell 路径，Linux 只验了 bash**）

- 准备：工作区里建个子目录 `sub\`，里面放个文件 `marker.txt`。
- 步骤：让 hermes：`在 sub 目录下列出文件`（观察它调 `run_powershell` 时传没传 `cwd`）。
- 预期：能列出 `marker.txt`；工具调用参数里出现 `cwd: "sub"`。
- 备注：模型不一定每次都用 `cwd`（也可能用 `Get-ChildItem sub`），那不算错——
  **本条真正要验的是：一旦传了 `cwd`，它在 Windows 上真能生效。** 若模型没用，
  直接说：`用 run_powershell 执行 Get-ChildItem，cwd 参数传 sub`。
- 实际结果：__________ ✅/❌

### TC-4.2 越界被拒（安全）

- 步骤：`用 run_powershell 执行 Get-ChildItem，cwd 参数传 ..\..`
- 预期：报错「拒绝访问工作区外的路径」，命令不执行。
- 实际结果：__________ ✅/❌

### TC-4.3 不传 cwd 照旧（回归）

- 步骤：让它在工作区根跑 `Get-ChildItem`。
- 预期：和以前一样，在工作区根执行。
