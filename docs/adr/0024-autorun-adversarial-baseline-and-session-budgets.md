# ADR 0024 — 自动放行的对抗性基线 + 会话级工具预算

- **状态**：已接受（2026-08-13）
- **相关**：ADR 0014（评估/策略架构）、`permissions.py`、`budget.py`、`agent/loop.py`
- **来源**：横向对比主流 agent 近期迭代（Claude Code 2.1.198–2.1.229、Codex CLI、Gemini CLI）后
  挑出的「A 档：便宜且确定」三项。

## 背景

对比下来 hermes 的工具面已与主流同代（hooks、压缩、plan mode、检查点、语义检索、MCP、技能市场都在），
个别处更细（`hardened_env()` 的非交互硬化、执行前剥 provider 计费密钥）。真正值得抄的是**别人已经
公开踩过坑并给出修法**的两类：

1. **权限检查绕过**。Claude Code 在 2.1.214 / 2.1.218 / 2.1.222 连修了一批 bash/PowerShell 权限检查
   绕过（空白填充、zsh `[[ ]]` 构造、引号、超长命令、`dir/**` 规则误放行嵌套目录）。hermes 的
   `command_is_safe()` 是**免确认**入口，判错方向不对称——多弹一次只是麻烦，误放行一条毁灭性命令是事故。
2. **会话级预算**。hermes 已有的预算全是**局部**的：`research_max_rounds`（一次研究催几轮重搜）、
   `delegate_max_revisions`（一个子任务回炉几次）、`crazy_max_*`（自主模式外层循环）。缺**整个会话里
   某个工具总共能调多少次**的闸。

## 决策 1 — 对抗性用例先跑事实，再决定改不改

**不凭猜测收紧规则**：先写探针把候选绕过逐条打到 `command_is_safe()` 上看它倒向哪边，
再只修真倒错的。首跑（2026-08-13，44 条）跑出 **4 类真绕过**：

| 手法 | 修法 |
|---|---|
| **换行当分隔符**（`ls\nrm -rf /`）——整条被当一段、首词 `ls` 命中只读白名单即放行 | `_SEG_SPLIT_RE` 加 `\n\r` |
| **单个 `&`**（bash 后台执行 / PowerShell 调用操作符） | `_SEG_SPLIT_RE` 加 `&` |
| **`env` 当执行器**（`env rm -rf /`）——白名单里唯一有双重身份的命令 | 只在无参或参数全是 `KEY=VALUE` 时放行 |
| **无长度上限** | `_MAX_AUTORUN_CHARS = 10_000`，超长一律确认（对齐 Claude Code） |
| 次要：`git grep -O` / `git diff --output=`——只读子命令 + 一个开关就能执行/写文件 | 拉黑并认「等号粘连」「值紧跟」两种写法 |

**同时记录了一条"不用改"的结论**：填充空白绕过（JS 侧栽过的那个）在这里天然不成立——
Python 的 `str.split()` 是 Unicode-aware，NBSP / 全角空格 / 垂直制表符都算空白。
这条**留了测试当证据**（`test_autorun_unicode_padding_is_already_safe`），
防将来有人把切词改成 `split(' ')` 之类把这个性质悄悄弄丢。

**纪律**：新增 `_SAFE_LEADING` 白名单命令前，先回 `tests/test_permissions.py` 加一条对抗用例——
判断标准是「这个命令能不能拿另一个命令当参数执行」。

## 决策 2 — 会话级预算：撞上限不执行，但回灌事实而非报错

`ToolBudget`（`budget.py`）按工具名计数，默认 `web_search` / `delegate` 各 200（对齐 Claude Code）。

三个关键选择：

1. **定位是跑飞止损护栏，不是日常约束**。正常会话摸不到 200 这个量级；它防的是跑偏任务
   （尤其 crazy 免确认模式）换着关键词无限搜、无限派子 Agent——每一次都通过所有局部检查，
   直到把 token 预算烧穿才停。
2. **撞上限时不执行该工具，但把「预算用尽 + 现在该怎么办」当作工具结果回灌**，与块 D/E/H
   「喂事实、不硬拦截」一脉相承：模型仍能用别的工具收尾作答，只是这一条路关了。
   区别于 gate 的 deny（那是安全判断），这里是**资源止损**。
3. **主 Agent 与所有子 Agent 必须共用同一个实例**。这是本功能的要害——每个子 Agent 各拿一份新预算
   等于上限形同虚设，正是「派 100 个子 Agent 每个搜 200 次」要防的洞。实现上走
   `Conversation._get_tool_budget()` 懒建复用，两个构造点传同一个（同 `failure_memory` 的做法）。

计数与判定在同一把锁内完成：并发子 Agent 不会因为「先各自读到 199」而一起挤过上限（有并发测试守）。
`tool_budget=None` → 完全不计数，存量调用方与测试零行为变化。

**闸放在 hooks / gate / 执行之前**：预算用尽就不该惊动用户去确认一次注定不跑的调用。

## 决策 3 — `run_bash` 补 `cwd` 参数，而不是做持久 shell

Codex CLI 把 shell 统一走 PTY（`unified_exec`），shell 状态跨命令保持。**hermes 不跟这条**：
`procs.py` 的后台进程 + `write_process_input` 已覆盖交互式场景的大半，补 PTY 的边际收益主要是
「程序检测到 tty 才输出进度条」这一小块，不值当。

但子目录执行这个具体痛点值得解：以前模型只能写 `cd sub && …`，那既多一段要过安全判定的命令
（`&&` 串接里**每段**都得在只读白名单内才免确认），跨平台写法也不一致。
现在 `cwd` 走 `Tool.resolve()`，受工作区/add-dir 约束（越界与非目录都报错）。
**这不是 shell 状态持久化**：每次调用仍是独立子进程，`cwd` 只作用于本次。

附带修正：报错定位（FR-13.B）改按**实际 cwd** 解析 traceback 里的相对路径——
传 workspace 会在 cwd 是子目录时找不到文件、定位块静默消失。cwd 缺省即 workspace，常见情形行为不变。

## 已知限制

- 白名单式判定永远可能有没想到的构造；对抗用例只证明**这批已知手法**被挡住了，不证明"安全"
  （文案纪律同 `skillscan`：不说"安全"，只说"这批已知绕过挡住了"）。
- 预算按**工具名**计数，不按成本计。一次 `delegate` 和一次 `web_search` 权重相同。
  真要按花费兜底，用的仍是 `crazy_max_tokens`。
- 预算随 `Conversation` 实例存活，不跨进程持久化——重启即清零。
