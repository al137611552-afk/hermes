# ADR 0026 — 站外协同：等待、唤醒、与重开提醒

- **状态**：已接受（2026-08-14）。**W1 已实现并真跑验证**（单测 10 条 + 真模型真跑 6/6，
  见 `scripts/diag_offsite_realrun.py`）；W2 暂不做，见分期。
- **相关**：ADR 0022（交互式命令 / `procs.py`）、ADR 0023（人机换手 FR-15）、ADR 0025（用量台账，
  用于验收这条能力值不值）、`bridge/conversation.py`（`_take_injects` / `_drain_injects_to_queue`）
- **来源**：用户观察到别的 agent 的一个闭环——**推 tag 触发 GitHub CI → 说一句"好了告诉你" →
  会话空闲 → 跑完自动回来报结果，红了自己修**——问 hermes 具不具备。查证结论是：**只缺四分之一步。**

## 背景

Agent 干活躲不开**站外协同**：结果不在本机产生、也不在本轮内完成。把那个闭环拆开是四步：

| 步骤 | hermes 现状 |
|---|---|
| ① 发起站外任务（推 tag / 调 API） | ✅ git 工具 + shell |
| ② 告诉用户"我会等，好了报你" | ✅ 就是一句话 |
| ③ **零成本等待 + 条件成立时唤醒，且回到同一上下文** | ❌ **缺** |
| ④ 醒来后自主处理（红了自己修） | ✅ 不需要新能力 |

**④ 看着神奇，其实不是独立功能**：它成立只因为 ③ 唤醒时**整个对话上下文还在**——模型记得为什么推
这个 tag、这批改动干嘛的、上一轮为什么红。若醒来是白纸，它只会复述"构建失败"然后不知道干嘛。
**唤醒必须回到同一个会话，不是起一个新的。**

**查证到的硬事实**（2026-08-14 读码）：

- `procs.py` 是**纯拉取**：只有 `read()` / `status()` / `waiting_prompt()`，读线程 `_reader()`
  在进程退出时**只是结束自己**，不 emit、不通知；
- 全库**没有任何调度 / 唤醒机制**（搜 schedule/cron/wake/timer 只命中技能扫描的规则串）；
- 工具清单里**没有 sleep/wait 类工具**；
- `Conversation.state` 是**纯内存**、初值 `idle`，**没有 resume**——关掉 app，"我在等 X"就没了。

**今天唯一能走通的路是 `/crazy` 自驱轮询**（`while rnd < budget`），但**很贵**：每轮"看好了没"
= 一次完整模型调用；会话被占住；还要撞 `crazy_max_rounds` 与 token 止损闸。**记下来免得后人
以为完全没路**，但它不是这条能力的答案。

## 决策 1 — 补的是「等待 + 唤醒 + 回到同一上下文」，不是编排器

范围严格限定在**等一件事**。**明确不做**：DAG / 任务编排器（那是另一个产品）、
在 agent 里重造 CI（站外系统已经做得很好，我们只要接上它的结果）。

## 决策 2 — 做成**已有工具的一个参数**，不新增工具

**实现时发现要两种形态**（源于用户点出的真正用途：*"有了它才能让 hermes 去调别的 agent
并且知道站外的进度"*）：

```
# ① 调别的 agent / 长跑软件：本地进程，退出即通知（不必轮询）
run_<shell>(command="claude -p '...'", background=true, notify_on_exit=true)

# ② 等站外的事（CI / 云端任务）：没有本地进程可等，只能问 —— 周期重跑直到 exit 0
run_<shell>(command="curl -s ... | grep -q completed",
            wait_until_success=true, poll_seconds=30, timeout_minutes=30)
```

**①几乎零成本**：`_reader()` 的 `finally` 本来就在进程退出时执行，以前只是自己结束、谁也不告诉，
加一行就成了"那件事干完了"的信号源。

**为什么不新造一个 `wait_for` 工具**：本项目已经踩过三次同一条规律——`trace_run`、`search_code`、
`request_handoff` 都是**机制建好了模型不用**（提示词里的旧路标压过新工具的 description）。
挂成已有工具的参数，模型不必学一个新概念才会用。

## 决策 3 — 只投递**事实**，不替模型下结论

条件成立时，往 `_take_injects()` 这条**已有的注入缝**投一条：进程/命令的 exit code + 尾部输出 +
等了多久。**不加"构建失败了，你应该去修"这类指导**——要不要继续、怎么继续由模型判断。
理由同 ADR 0025 的成本纪律：**给事实，不给替人做的决定**。

## 决策 4 — 关窗口 → **重开时带着答案提醒**，不自动重建等待器

桌面形态与服务端 agent 的关键差别：**服务端进程通常一直活着，桌面的必然会被关。**

选择（2026-08-14 用户拍板）：**只持久化"在等什么、从什么时候开始"这一行**，重开时读出来提醒；
**不在启动时重建轮询**。

**为什么不自动续等**：自动重建要重新起轮询、连网、判活，给启动加一段不确定的等待；
而**用户此刻的注意力本来就在这儿**（他刚点开 app），问一句的成本几乎为零。
**打扰的成本 = 把注意力拉回来的代价**——注意力已经在场时，提醒不算打扰。

**提醒前先查一次**（2026-08-14 用户采纳）：重开后**异步补查一次**条件是否已成立
（一次请求，零模型成本，**不挡启动**），再开口。于是说的不是"你上次在等 CI，还等吗"，
而是"你上次等的 CI 已经跑完，第 15 轮全绿，要我接着定版吗"。
**带着答案的提问，比问一个你不知道答案的问题好**——尤其在这个场景里，等待期往往比 app 关闭期短，
**大概率一查就有结果，那一问就从"要不要继续等"变成"要不要接着干"**。

**三种结局分开说**（同 ADR 0025 的纪律，含糊的"已处理"会让人不知道下一步）：
① 已完成 → 报结果 + 问要不要接着干；② 还在跑 → 问要不要继续等；
③ 查不到/查失败（tag 被删、仓库改名、断网）→ **如实说查不到**，别装作还在等。

## 决策 5 — 轮询即可，**不做公网 webhook 接收**

要么开公网口、要么挂隧道，安全面与运维成本跟收益不成比例。接 GitHub 事件**轮询就够**。
唯一例外是 **loopback 回调**（OAuth 登录用，ROADMAP 第三档 1）——那是本机监听、随用随起随关，
与公网入站是两回事，**做 OAuth 时顺手把这个口开出来**，不为它单独立项。

## 由此能覆盖的场景（同一组原语，不是五个功能）

- **等异步结果**：CI/部署、云端评测、批量推理、大查询、转码渲染；
- **等人在别处做完**：PR 被合并、工单被处理、审批通过。
  ⚠ 这与 `request_handoff`（ADR 0023）**互补不重叠**：换手是**同步阻塞**（挂起等人接管），
  而这里是**异步**——人在**别的系统**里完成，做完之后"怎么通知回来"，现在这条路是断的；
- **跨会话推送**：hermes 已有拉取式共享（`recall_history` / FailureMemory / 产物按 id 读），
  缺的是"A 会话干完通知 B 会话"，同样落在唤醒上；
- **定时**（每天跑一次回归 / 定期重跑评测基准）：最便宜也最不急，**等真开始跑定期评测再说**。

## 已知限制

- 等待期间 hermes 被关 → 按决策 4，不续等，重开提醒。
- 轮询有下限粒度（秒级），不适合要求毫秒响应的场景——本项目没有这种场景。
- `wait_until` 是**模型给的命令**，写错了就是白等到超时。故 `timeout_minutes` 必填有上限，
  超时也投递事实（"等了 30 分钟条件仍未成立"），**不许无声挂死**。

## 真跑验到的（2026-08-14，DeepSeek）

**A 机制**——第一轮："好的，我等它完成"（这一轮到此结束、会话空闲）→ 后台进程 3 秒后退出 →
**没有任何人再输入**，第二轮自动起来："构建完成了（后台进程 #1，退出码 0），输出：`BUILD_OK_42`"。
注意它说的是"**构建**完成了"——**它知道这是第一轮里说要等的那件事**，不是干巴巴复述"进程退出了"。
这就是"回到同一上下文"生效的样子，也是整个 W1 的意义所在。

**B/B2 模型会不会自己用**——B（提示里写了"我不想你反复回来查"）用了，但**这条不算数**，
提示几乎把答案说了。故补 **B2 中性提问**（"帮我在后台跑一下 X，跑完把结果告诉我"，零暗示）
**也用了**——参照 `delegate_implicit` 评测任务的思路（"精简 prompt 曾在此翻车"）。
**B2 过了，才说明这次没重蹈"机制建好了模型不用"的覆辙**；这条永久留在脚本里当回归，
将来谁改瞎了工具描述一跑就知道。

**边界**：只在 DeepSeek 上验过。按既有教训（"强模型在小库上绕开专用工具"），
不同模型的选择倾向可能不同；脚本支持换 `HERMES_RT_*` 验别家。

## 验收判据（写在前面，防止建好了没人用）

上线后观察**半个月**：用 ADR 0025 的用量台账看这条路径**被用了几次**。
**若基本没被用过，就按 C 档的规矩记下理由并撤掉**——照 delegate 后台化的先例
（"机制建好了模型不用"是本项目验证过三次的规律，不是假想风险）。
