# ADR 0025 — 用量与成本台账（token accounting）

- **状态**：草案（2026-08-14）
- **相关**：ADR 0008（会话持久化）、ADR 0024（会话级工具预算）、`providers/anthropic_p.py`、
  `providers/openai_p.py`、`agent/loop.py`（`emit("usage")`）、`web/pure.js`（`accumulateUsage`/`estimateCostUsd`）
- **来源**：讨论「如何优化 模型+harness 这个系统工程」时的推论——**模型是外部给定、按 token 付费的输入**，
  于是"人的时间"与"模型的钱"必须并排看，否则无法判断一个 harness 改动是赚是亏。

## 背景

现有用量统计的数据链路是通的：

```
provider._usage() → StreamEvent.meta["usage"] → loop.py 跨步累加 → emit("usage") → 前端 accumulateUsage → 顶栏 chip
```

但**每一环都有洞，且都是"静默算错"**——不报错，只给一个自信的错数。逐条体检（2026-08-14 读码）：

| # | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| 1 | **缓存写没采集** | `anthropic_p._usage()` 只取 `input/output/cache_read` | 漏 `cache_creation_input_tokens`，而写缓存比普通输入**贵** |
| 2 | **`cache_read` 写死 0** | `openai_p.py` | DeepSeek 的 `prompt_cache_hit_tokens`/`miss_tokens` 整个被丢——**正是"命中/未命中"** |
| 3 | 缓存读一律按输入价 **10%** | `pure.js estimateCostUsd` | 各厂商折扣不同，一个常数覆盖所有必然错 |
| 4 | **币种写死 USD** | `MODEL_PRICING` | DeepSeek/Kimi/方舟按人民币计价，现在硬塞成美元估值 |
| 5 | 模型名**子串匹配** | 同上 | `deepseek` 一条覆盖全系（价格不同）；`opus` 会误匹配自定义档名 |
| 6 | **端点不报 usage 时静默当 0** | `openai_p` 返回 `usage=None` | **看起来这轮免费**——比不显示更糟 |
| 7 | **完全没落库** | 全在前端内存 | 重启清零、历史回放无用量、无法跨会话/模型/版本比较 |
| 8 | 无时段折扣概念 | — | 有错峰折扣的厂商按牌价算永远偏高 |

**结论：不是"缺个面板"，是采集、计价、存储三层都要重做。** 面板只是它的出口。

## 决策 1 — 只入库事实，金额在渲染时算

**库里存 token 数，不存金额。** 成本 = 查价目表 join 出来。

**为什么**：价格会变、会填错、会有折扣。**金额一旦落库，将来改价目表就无法重算历史**——你会得到一堆
按不同时期价格算出的、无法相互比较的数字。存事实则永远可重算。

**`usage_log`（事实表，一轮一行）**

```
ts, session_id, turn
model_profile         # 档名（用户看到的）
provider, model_id    # 真实发给 API 的模型名 —— 计价按它，不按档名（决策 4）
input_uncached        # 未命中缓存的输入
input_cache_write     # 写缓存（单独计价）
input_cache_read      # 命中缓存
output
reasoning             # 思考型模型单独计价的部分（预留，暂可为 0）
measured              # 1=API 实报 / 0=我方估算（决策 3）
agent_role            # main / delegate:<name> / review:<role>（决策 5）
harness_version       # 便于跨版本比较同一批工作的成本
request_id            # 便于跟厂商后台账单对账（决策 6）
```

**缓存三态必须分开存**，不能合并成一个 `cache` 字段：写、读、未命中三者**单价不同**，合并即丢失可算性。

## 决策 2 — 价格只来自**用户手填**（+ 随包牌价兜底），**明确不做联网抓取**

| 优先级 | 来源 | 说明 |
|---|---|---|
| ① 权威 | **用户手填** | 设置面板的模型档里填：币种 / 输入 / 缓存写 / 缓存读 / 输出 / 生效日期 |
| ② 兜底 | 随包内置牌价 | 带 `as_of` 日期，明标"公开牌价、仅供粗估"；**超期就在 UI 标黄** |

**为什么以用户手填为权威**：只有用户知道自己的真实单价——企业协议价、代理商价、订阅额度、阶梯价，
**官网牌价对他们根本不适用**。把牌价当权威等于系统性地算错。

**为什么不做联网抓取**（2026-08-14 用户拍板不做；理由记于此，防将来重复讨论）：

- 定价页是**营销页面**，结构频繁变，混着促销价、阶梯价、时段折扣；
- **抓错了不会报错，只会静默算错钱**——那是给"统计不准"这个问题**新增一个来源**，与本 ADR 的目的相反；
- 手填一次的成本远低于"维护 N 个厂商的抓取规则 + 每次抓完还要人核对"。

**`model_prices`（价目表）**

```
provider, model_id, currency          # 币种是一等字段，不是隐含 USD
price_in, price_cache_write, price_cache_read, price_out
as_of, source(user|bundled), note
```

## 决策 3 — 没有可信价格就**只显示 token，绝不显示金额**；估算与实测必须可区分

两条不变量：

1. **价目表匹配不到 → 只显 token**。现有实现已是这个原则（"匹配不到则不显示成本"），**保留并加强**。
2. **`measured=0` 的行在 UI 上打「估」**。端点不报 usage 时，用 `context.py` 已有的启发式
   （ASCII≈4 字符/token、中文≈1 字符/token）填上，**但绝不冒充实测**。

**理由**：这跟技能安全扫描那条文案纪律同源——**一律不说"安全"，只说"未发现可疑信号"**。
成本这里就是：**宁可少一个数，不给一个错的数**。一个自信的错数会被拿去做决策，比缺失危险得多。

## 决策 4 — 按 `model_id` 计价，不按档名；不做汇率换算

- **计价键是真实 `model_id`**，不是用户起的档名。档名可以叫"我的主力"，价格得跟着背后的模型走。
  也因此**废弃子串匹配**（`opus` 命中任意含该词的档名是隐患）。
- **不做汇率换算**：多币种**分币种显示总额**，不合并。汇率天天变，合算就又制造了一个会漂的错数。
  用户真想要一个总数，可以自己填一个折算率——那是他的假设，不是我们的。

## 决策 5 — 按 agent 角色归因

主 agent 与子 agent（delegate）、评审各角色**分别记账**。

**为什么**：`budget.py` 的会话级预算是**主子共用一份计数**（ADR 0024，各拿一份等于没上限），
但**计数共用不等于记账也该共用**——"钱花在哪个子 agent 上"正是优化 harness 时最想知道的事。
没有这一维，你只知道"这次会话花了 3 块钱"，不知道该砍哪里。

## 决策 6 — 提供对账手段

记 `request_id`，并支持导出某时间段的用量明细。

**为什么**：本 ADR 的目的就是"统计别是错的"，那就必须能**验证统计本身**。
跟厂商后台账单核一次，对不上就说明采集还有洞。**"看起来挺合理"不是验证。**

## 决策 7 — 独立 `usage.db`，不进 `hermes.db`

用量落在**独立库**（2026-08-14 用户拍板）。

**为什么**：用量是**审计性质**的数据，不该跟着会话生命周期走——**删一个会话不该把账一起删掉**，
否则"这个月花了多少"随时会因为清理会话而变小，统计再次变得不可信（与本 ADR 的目的直接冲突）。
同时它与会话库的读写模式也不同：会话库是交互式读写，用量是只追加 + 批量聚合查询。

**代价**（明确接受）：多一个库文件；跨库关联（如"这条会话花了多少"）要按 `session_id` 自己拼，
不能靠 SQL join。可接受——聚合查询本来就以时间/模型/角色为主键，按会话查是次要路径。

**连带**：`pack.py` 的排除项已含 `*.db`，`usage.db` 天然不进分发包；
CI 的「断言产物不含 .env / 密钥」那步也会顺带挡住它。

## 已知限制

- **订阅制无法用单价表达**。若将来接订阅登录（ROADMAP 第三档 1），那种档位的成本不是 token×单价；
  面板应允许把某档标为「订阅制」，只统计 token、不出金额。
- **阶梯价 / 时段折扣不建模**。用户可手填一个折后均价，但那是近似。
- **历史无数据**：从落库上线那天起才有，之前的会话补不回来。
- **估算误差**：`measured=0` 的行只是数量级正确，不可用于对账。
- **不做预算告警**（超支拦截）。本 ADR 只管"看得见"，拦截是另一件事（且已有工具预算作先例）。

## 交付分期

| 期 | 内容 | 自测边界 |
|---|---|---|
| **P1** | 落库 + 采集补全：新库/新表、provider 三处补齐（缓存写 / DeepSeek 命中未命中 / OpenAI cached_tokens）、`measured` 标记、role 归因 | ✅ Linux 可完整自测 |
| **P2** | 价目模型 + 成本重算：多币种、缓存三态分算、`as_of` 过期标记，替换 `estimateCostUsd` | ✅ 纯逻辑单测 |
| **P3** | 用量面板 UI | ❌ **需 Windows 真机验** |

**P1+P2 先做**：即使面板还没有，数据已经在攒，而且是对的。**面板可以晚，采集不能晚**——
没采的那段时间永远补不回来。

## P3 的 UI 纪律（本项目已踩过的坑，实现时照此避让）

- **新面板必须入浮层栈** `pushLayer/popLayer`——不入栈则 Esc 被下层吃掉，自挂的监听收不到事件。
- **别蹭 `.settings-body` 等老类**——`style.css` 是按功能顺序追加的大文件，后写的同特异性规则永远赢，
  蹭老类会被压成一列竖排字。要么完全自带样式，要么用 `.a.b` 提特异性。
- 有 `display:` 的元素**必须补** `.x[hidden] { display: none; }`，否则 `el.hidden=true` 仍显示。
- 宽表格用外层 `.table-wrap` 滚动，**别给 `table` 加 `display:block`**（WebView2 滚动坑）。
