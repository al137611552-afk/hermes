# ADR 0023 — 人机换手：接管点（handoff）与轨迹固化（轨迹 → 技能）

- 状态：**已接受并落地**（2026-08-12，v3.63.0）。决策 1~3（换手）与 4~8（轨迹固化）全部实现，
  **Windows 真机 + 真模型验证通过**。落地时对决策 1 补了一条前提、对决策 8 的顺序做了调整，
  见下「实现说明」。
- 日期：2026-08-12
- 关联：[0014 技能包](0014-agent-skills.md)、[0013 MCP 工具集成](0013-mcp-tool-integration.md)、
  [0019 方案评审](0019-design-review-mode.md)、[0021 工具产物与句柄](0021-tool-artifacts-and-handles.md)；
  PRD FR-13.C2（一键技能化）、v3.43 浏览器登录态穿透

## 背景

外部信号（2026-08，xAI Grok Bot 早期测试版，媒体口径未独立核实）把两件事摆到了同一张产品图上：
**"跟班学习"**（人做一遍，bot 记录步骤并复用）与**"递权给人"**（遇到登录/SSO 等人为决策点主动交还控制权）。
剥掉云端 VM 那层叙事后，这两条其实是**同一条通道的两半**：agent 与人之间的**换手**——
一半是"我做不了，你来做"，另一半是"你做给我看，以后我照做"。

hermes 现有地基能接住这条通道的大部分：

- **技能**（ADR 0014）已是规范化的固化载体：目录 + `SKILL.md` + 渐进披露 + 按需 `load_skill`。
- **`/技能化`**（FR-13.C2，v3.59.0）已证明"提示词流水线写 SKILL.md + 自检"这条出口可用，无需新造技能编辑器。
- **`ask_user`**（`tools/ask.py`）已有 emit + `threading.Event` 阻塞 + 前端 resolve 的成熟桥模式。
- **浏览器**：Playwright MCP 已接（`_BROWSE_TOOLS` 白名单，snapshot 为 ref 式、非视觉可下钻），v3.43 已打通登录态穿透。

缺口是三条：

1. **换手是模糊的**。agent 碰到登录/验证码/支付只能 `ask_user` 问一句；问完**不强制重新观察**，
   而 crazy/无人值守下 `AskUserBinding.set_auto` 会直接"按合理默认继续"——在登录这类**不可代办**的环节，
   这等于**制造假成功**，与 crazy "完成判定只认未被截断的主动收尾"的既定纪律冲突。
2. **一次跑通的做法没有低摩擦的固化入口**。`/技能化` 面向的是"一个程序"，不是"刚才这段过程"。
3. **人在 hermes 之外的做法进不来**。尤其调研：去哪些站、怎么找到数据区、哪个信源更权威、看到什么算够——
   这些判断今天完全靠模型现推，而人其实有成熟套路，只是没有通道交给 hermes。

## 决策

### 1. 一条通道，两个用途：`handoff`（换手）作为一等状态

新增工具 `request_handoff(reason, target, resume_hint)`，桥接方式照抄 `ask.py`/权限 gate（emit + Event 阻塞 + resolve）。
与 `ask_user` 的区别是**语义与行为都不同**，故不复用：

| | `ask_user` | `request_handoff` |
|---|---|---|
| 语义 | 让人**拍板**（选项择一） | 让人**动手**（agent 做不了） |
| 无人值守 | 按合理默认放行 | **绝不放行**（见决策 2） |
| 恢复后 | 拿到答案继续 | **强制重新观察**再继续 |

换手面板必须显示**当前真实目标**（URL / 应用 / 文件路径）与发起理由，并明示
**"你在此处输入的凭据只留在浏览器 profile，hermes 不读取、不回传"**。
理由：换手本身是降风险动作，但它同时是个天然的钓鱼位——恶意技能可以写"请求换手并引导用户在某页登录"。
显示真实来源 + 凭据边界声明，是把 ADR 0014 决策 4「兼容格式，不兼容其信任假设」的姿态延续到交互层。

### 2. 无人值守模式下，换手挂起而不是跳过

crazy / 自主模式遇到 `request_handoff`：**挂起任务并标记「阻塞：待人工换手」**（有通知能力则推送），
预算超时后按**阻塞**收尾，**不得**记为完成、不得按默认继续。

理由：登录、验证码、支付、真人身份验证在原理上不可代办，自动放行只能产出自欺欺人的结果。
这与 v3.22 "撞上限/被打断一律不算完成"是同一条纪律。

### 3. 换手回来必须重新观察，不许假设

人点「我做完了」之后，agent 的下一步**强制**是一次状态重读（浏览器场景 = `browser_snapshot` + 当前 URL；
文件场景 = 重读目标文件），确认换手确实达成目标才继续。
理由：用户点完成但其实没登上，是这类交互最常见的失败模式；靠 prompt 叮嘱不可靠，走**结构约束**
（v3.43 教训：结构性约束 > prompt，且要盖全入口）。

### 4. 轨迹**只由人手动开关**，不做自动检测与自动固化

- 按钮位置：**撤掉输入框旁的 `#review-btn`**（`web/index.html:124`），原位改为 `#trace-btn`「轨迹」。
  评审保留消息上的「🔬 评审这段」入口（`web/app.js:317`）——方案在哪一轮就点哪一轮，本就比猜最后一条准，
  composer 上那个入口是冗余。
- 轨迹按钮是**开关**：点亮=开始录制，再点=结束并进入固化。录制中在 composer 上方常驻状态条
  （已录 N 步 / 时长 / 停止 / 丢弃），防止忘关。

**否决自动固化**，理由有三：
- 判据不可靠：保守则永不触发，激进则批量生成垃圾技能。
- 反噬渐进披露：ADR 0014 决策 2 的前提是**技能清单的价值密度**——`description` 就是路由表，
  噪声技能直接毁掉模型的技能选择，代价远高于漏掉几个该固化的流程。
- 人工信号极强：用户点下按钮那一刻，等于明确宣告"这类事我还要再干"。没有任何启发式能比这更准。

### 5. 录什么：三层来源，只做前两层

**T1 · 会话内轨迹（默认模式）** —— 录 hermes 自己的动作：工具调用序列（工具名 + 关键参数 + 结果摘要）、
产出的 artifacts 句柄（ADR 0021）、以及**用户中途的纠正消息**（"不对，应该先 X"——纠正是最高密度的信息）。
数据本就在 SQLite 会话与产物存储里，采集 = 打标记 + 归并，不新增采集面。

**T2 · 浏览器人类演示（「我来演示」模式）** —— 面向调研/取数这类跳出 hermes 的做法。采集方式：

- **不录屏、不做视觉重建**（成本高、噪声大、不可靠）。
- 载体是**受控 Playwright 实例**（不附着用户日常 Chrome）：干净、可控、隐私面小，复用已接的 MCP 浏览类白名单。
  代价是没有日常登录态、演示时要现场登录——而这正好走决策 1 的换手通道，**两个特性互相验证**。
- **以人工打点为主**：人在关键处点「记一步」，附一句话说明（例如"这个站的年报数据比二手媒体准"），
  hermes 于该时刻采集 URL + `browser_snapshot`（a11y 结构，非像素）+ 滚动深度/停留时长。
  不做定时全量快照——定时采集会录进大量无意义中间页，把信噪比压垮，逼模型从噪声里挑，
  而**打点本身就是人在标注"这一步重要"**，信息密度高一个量级。
- **旁白是一等公民**：录制期间人可随时在输入框打字说明意图，旁白与快照按时间轴对齐。

  理由：**意图不可能从点击流里推断出来**。"他点了第三个链接"没有信息量，"我只信一手年报"才是要固化的东西。
  这也是本方案与 RPA 录制的根本分野。

**T3 · 桌面级演示（浏览器与 hermes 之外的客户端）** —— **明确不做**，范围外，成本失控。

### 6. 产出是 **SOP 技能**，不是回放脚本

固化结果写进 `SKILL.md` 的是：这类任务去哪几类站、每站怎么定位到有效区、信源优先级、
什么算"查够了"、以及可执行的验收（沿用内置 `research-report` 带 `scripts/check_report.py` 的做法）。
回放时由模型**带着 SOP** 用 `web_search`/`web_fetch`/浏览类工具自己走。

**否决确定性回放**：页面一改版就碎，维护是必输的军备竞赛（同 v3.27 "反爬别硬刚"的同源教训）。
稳定性来自"固化步骤 + 可程序化验收"，不来自坐标与选择器。

### 7. 参数化是固化的必做步骤

草案生成时把具体值（路径、账号、日期、公司名、目标文件、具体站点）抽成 `{{变量}}` 并给示例值。
理由：这是"**这次的事**"变成"**这类事**"的唯一关键动作，也是轨迹技能区别于"存一份聊天记录"的本质。
不做参数化的固化不如不做。

### 8. 固化出口复用 `/技能化` 的提示词流水线

结束录制 → 把归并后的轨迹（步骤 + 旁白 + 纠正 + 参数化候选）喂给与 `/技能化` 同源的提示词 →
模型草拟 `SKILL.md` → **草案面板**里人改（名字 / description / 步骤 / 变量 / 验收）→ 确认落盘。
落盘走 ADR 0014 既有查找链路（默认 `<工作区>/.hermes/skills/<name>/`，可选全局），**核心零改动**。

## 备选与权衡

- **自动检测重复轨迹并建议固化**：否决，见决策 4。连"只记一行日志不弹窗"的弱化版也不留——
  半吊子开关只会变成没人看的噪声。
- **录屏 + 视觉理解重建步骤**：否决。成本高、不稳、还把隐私面拉满。
- **CDP 事件级录制（精确点击/输入）**：**推迟**。需要自建 CDP 客户端 + 注入监听脚本（新依赖面），
  而它换来的精度（像素级复现）恰恰不是本方案要的东西（决策 6）。列为已知限制，等 T2 真跑发现
  "快照序列不够用"再上。
- **用 `ask_user` 表达换手**：否决。无人值守下两者行为**相反**（一个必须放行，一个绝不能放行），
  合并会让 crazy 模式默默走错路。
- **把轨迹做成新的持久化子系统**：否决。轨迹是**一次性素材**，用完即转成技能；
  不建独立存储、不建检索层（ADR 0014 不变量：物化你要学习的，别建你不需要的引擎）。
- **演示时附着用户日常 Chrome（CDP）**：否决（2026-08-12 拍板）。它能带来真实登录态与最贴近日常的演示，
  但 hermes 会看见用户全部标签页与站点，隐私面和误操作面明显更大，还要处理 CDP 端口/profile 占用。
  受控实例缺的登录态由换手补齐，收益不足以换这份风险。
- **定时快照为主**：否决（2026-08-12 拍板），见决策 5 T2。

## 验收（真机 · Windows + 真模型）

1. **换手**：让 agent 去一个需登录的站取数 → 弹换手面板（显示真实 URL）→ 人登录后点完成 →
   agent **重新 snapshot** 确认已登录再继续；人未真正登录时 agent 能识别并再次请求换手。
2. **换手 · crazy**：crazy 模式下同一任务 → **不自动放行**，任务收在「阻塞：待人工换手」，不记完成。
3. **轨迹 T1**：跑通一个多步任务 → 点轨迹结束 → 草案含步骤与 `{{变量}}` → 落盘 →
   新会话中模型据 `description` 自行 `load_skill` 并复用成功。
4. **轨迹 T2**：开「我来演示」→ 人在受控浏览器走一遍调研路径 + 打点 + 旁白 →
   草案里含站点清单、定位方法、信源优先级、验收 → 换一个同类问题，模型带 SOP 独立完成，质量优于无技能对照。
5. 全量回归绿；`pure.js` 与 `trajectory` 归并/参数化、handoff 挂起/恢复/超时/crazy 不放行均有单测。

## 实现说明（2026-08-12 落地时的偏差）

**决策 1 的一条隐含前提，真机验证时才浮出来：换手要成立，人必须**有地方动手**。**
hermes 的浏览器是**独立 profile 的受控实例**，默认跑在**无头**模式——此时把控制权"交还"用户，
他在自己日常 Chrome 里登录，hermes 那个 profile 完全看不见，于是永远验不过、只会反复请求换手。
落地补法：网页类换手（target 是 URL）的面板会先问一次浏览器状态，并据此给三种话术——
①未启用穿透＝此路不通，别白登；②无头＝**一键切到有头并打开这一页**（走既有的 `set_browser_headed`
热重连），在弹出的窗口里登录；③已有头＝仍点明"是弹出的那个窗口，不是你平时用的 Chrome"。
这也正好印证了决策 5 T2 里那句"受控实例缺的登录态由换手补齐"——**前提是那个实例得有窗口**。

**决策 8 的人审环节前移了一步。** ADR 原文是「模型草拟 `SKILL.md` → **草案面板**里人改
（名字 / description / 步骤 / 变量 / 验收）→ 确认落盘」。实现改成：

**结束录制 → 轨迹面板里人改（勾掉步骤 / 改变量名 / 定技能名与 description / 选落盘范围）→
确认后拼成指令、走正常发消息交给 `skill-creator` 流水线 → 模型据此写 `SKILL.md` 并落盘。**

理由：①人审的**目的**（不让垃圾技能自动进技能清单）在两种顺序下都成立，而在轨迹这一层改
**信息更少、更好改**——`SKILL.md` 草案是模型的成品，让人在富文本上做结构化编辑要新造一个编辑器，
恰恰是决策 8「不另造技能编辑器」想避免的；②模型写出的 `SKILL.md` 本就是工作区里的普通文件，
人可以在预览面板里直接改、技能自带的自检也照跑，第二道闸并没有丢；③固化指令以**正常消息**
发出（用户看得见、能改、能撤），不是暗箱调用。

代价：人无法在落盘**前**逐字审模型写的 SOP 正文。真机验证时重点看这条够不够用——
不够就再补一个"落盘前先给我看"的确认步（届时记进本节，不改上面的决策）。

## 已知限制与待定岔路

- T2 要求人配合打点。人只顾操作不打点时，轨迹会退化成一串裸 URL——面板需在"长时间无打点"时轻提示一次
  （只提示，不打断）。
- T2 只录浏览器；人若中途切到桌面客户端，轨迹会有断点（面板需显式提示"这段没录到"）。
- 受控实例每次演示需现场登录（走换手）；不做凭据代管，这是刻意取舍。
- 无像素级复现能力（刻意，见备选）。
- 固化质量上限受模型写作能力约束；缓解手段是草案面板必须人过一遍 + 技能自带可执行验收。
