# ADR-0015: 技能市场（下载/安装）与安装前本地安全扫描

- 状态：已接受
- 日期：2026-08-07
- 关联：[ADR-0014](0014-agent-skills.md)（技能包本身）

## 背景
ADR-0014 落地了技能机制，但技能得靠用户自己往目录里放文件。用户提出要"像主流那样能简易
下载/配置，社区里评分高的技能让用户自己选择是否安装"。

外部现状（2026-08 核实）：
- **分发模型已成型**：Claude Code 的 `/plugin` 体系把「市场」定义为一个 git 仓库，仓库根放
  `.claude-plugin/marketplace.json`（有公开 JSON Schema）。用户 `marketplace add <repo>` 加源、
  `install <name>` 装。已有官方市场与多个大型社区市场。
- **注册表 UI 的共识**：按分类/标签/排行榜浏览、⌘K 搜索、每个技能一行安装命令。
- **信任 UX 是标配**：`agentskills.codes` 给每个技能 **clean / review / warn 三档静态安全扫描
  分级 + 能力标记**，并显示 GitHub 源的 stars / license / last-commit，目录每天重扫。

结合 ADR-0014 已记录的风险（技能是特权攻击面、实证约 26.1% 公开技能索要危险权限），
"能一键装第三方技能"这件事必须和"装之前看得见风险"一起做，否则是在给用户递刀。

## 决策

### 1. 格式对齐 Claude Code 的 `marketplace.json`，不自造市场格式
解析 `.claude-plugin/marketplace.json` 的既有字段，`source` 支持相对路径、`github`、
`git-subdir`、指向 GitHub 的 `url`。**理由**：现有社区市场不用改一行就能被 hermes 读
（实测官方市场 13 条目、社区市场 88 条目全部解析成功）。

**明确不支持**：npm 来源、非 GitHub 的 git 主机——会给出可读原因而不是静默失败。
不为此把 git / npm 拉成硬依赖。

### 2. 下载走 GitHub zip 归档，不走 `git clone`
标准库 `urllib` + `zipfile`，**零新依赖**、不要求用户机器装 git。
实测社区市场 88 个条目**全部**是 `"source": "./相对路径"`——下载一次市场仓库归档就拿到全部插件。

解压做了完整防护：拒绝绝对路径与 `..`（zip slip）、跳过符号链接、限制条目数（2 万）
与解压总字节（200MB，防 zip bomb）、限制下载大小（80MB）。

### 3. 安装前**本地**静态扫描 + 三档分级确认（本 ADR 的核心）
沿用社区的 clean / review / warn 命名（便于与外部标记对齐），但**扫描在本地做**：

| 分级 | 触发 | 前端行为 |
|---|---|---|
| clean | 无命中 | 直接安装 |
| review | 网络外发 / 读取凭据 / 提权 / 隐藏内容 / 声明敏感工具 | 一次确认 |
| warn | 远程代码执行 / 混淆执行 / 破坏性命令 / 改 shell 配置 / Markdown 里的提示注入 | 二次确认，按钮标红，默认不装 |

**为什么本地扫而不用外部服务给的分数**：不把"这个技能安不安全"的判断权外包出去，
且离线可用。**为什么是"确认"而不是"拒绝"**：延续项目「危险操作要确认、不硬拦」的一贯姿态
（同 ADR-0013 对 MCP 外部工具的处理）；启发式误报必然存在，把决定权留给用户。

**措辞纪律**：三档文案与小结**一律不出现"安全"二字**，只说"未发现可疑信号"，并显式声明
"这是启发式扫描，扫不出刻意混淆的内容"。已用测试钉死（`SKILL_GRADES` 文案不得含"安全"）。
截断扫描时必须说明"只扫了一部分"——否则"未发现可疑模式"会被误读成"扫遍了都干净"。

### 4. 命名：**接收时宽容、产出时严格**（真跑逼出来的改动）
规范要求 `name` 全小写连字符且与目录名一致。**实测发现现实中普遍不遵守，连 Anthropic 官方的
`plugin-dev` 插件也不遵守**——它 7 个技能的 name 全写成 `Agent Development` 这种形式。
严格按规范拒绝的结果是：**hermes 装不了绝大多数真实技能，包括官方的**。

因此：读第三方技能时把 name 归一化成合规 slug（`normalize_name`）；`name` 与目录名不一致时
**回退用目录名**作权威名（与 Claude Code 文档描述的 fallback 一致），而不是把技能丢掉。
写我们自己的技能仍走 `strict=True` 严格校验，并由测试守住内置技能全部合规。

### 5. 浏览分两阶段（浅拉 → 深扫）
`browse_skill_market(repo)` 只拉 marketplace.json（秒回）；`deep=True` 再下载仓库归档，
数清每个条目**实际含几个技能**。前端先出列表、再后台深扫更新计数，并把 0 技能的条目滤掉。

**为什么需要**：Claude Code 插件可以只含 commands / agents / hooks 而没有任何 SKILL.md
——实测官方市场 13 个条目里**只有 4 个含技能**。不深扫的话，用户要点进去等下载完
才发现"这个装不了"。

### 6. 安装路径受限
`Api.install_skill` 只接受市场缓存目录（`<APP_DIR>/data/skill_cache/`）下的路径，
防止前端传任意路径把机器上别处的目录拷进技能库。卸载同样做越界检查。

## 备选与权衡
- **接第三方注册表 API（agentskills.codes / skills.sh）**：技能量最大（数千个），但无标准 API、
  依赖外部服务可用性，且等于采信别人的安全评分。**否决**，改为支持用户自行添加任意市场仓库。
- **只做内置精选清单、不开放自定义源**：最安全但技能少、清单要人工维护。**否决**，
  改为"内置精选（已核实）+ 用户可加任意源"。
- **高危直接拒装**：与项目「确认而非禁止」的一贯做法冲突，且误报时用户没辙。**否决**。
- **用 git clone 下载**：要求用户装 git、且 Windows 上 spawn 昂贵（FR-10.1 踩过）。**否决**。

## 已知限制
- 扫描是**启发式**的，刻意混淆（多层编码、运行时拼接）扫不出来。这一点在 UI 上明说，不藏。
- 无供应链校验：不校验 GitHub 仓库归档的签名/哈希，也不锁定版本；重装即拿最新。
- 精选清单里的条目数是核实当天的快照，会随上游变化；清单本身需人工维护。
- 只支持 GitHub 上的公开市场仓库（私有仓库需凭据，未做）。
- 装进来的技能不自动更新，也没有"检查更新"入口（覆盖安装可手动更新）。
