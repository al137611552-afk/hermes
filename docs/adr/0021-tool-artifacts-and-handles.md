# ADR 0021 — 工具产物化与句柄（大输出可寻址）

- 状态：**已接受**（2026-08-10 评审通过，五个问题已拍板，见文末「评审决议」）
- 日期：2026-08-07（评审定稿 2026-08-10）

## 背景

现在所有工具输出都是「一段字符串塞进上下文」，超限就**截断丢弃**：

| 工具 | 上限 | 超限行为 |
|---|---|---|
| `read_file` (`fs.py`) | 200,000 字符 | 截断，提示可用 `offset` 续读 |
| `run_<shell>` (`shell.py`) | 200,000 字符 | 截断 |
| 后台进程输出 (`procs.py`) | 200,000 字符/进程 | **环形缓冲**，早期输出被覆盖冲掉 |
| `web_fetch` | 默认 20,000 字符 | 截断，或按 `focus` 摘录 |
| `list_dir` | 1,000 条 | 截断 |
| `grep_search` | 行截断 2,000 + 8s 墙钟 | 截断 |

问题不在"有上限"（上限是对的，防灌爆上下文），而在**截掉的部分永久消失**：模型想再看只能**重跑一遍**同一条命令/请求——重跑既贵又未必幂等（网页变了、构建产物变了、后台进程的早期日志已被环形缓冲冲掉，**根本重跑不出来**）。

真实场景：
- 跑一次全量测试输出 40 万字符 → 只看到后 20 万，前面的失败摘要没了 → 只好再跑一次；
- 抓一个 GitHub 仓库页 46,000 字符正文 → 默认 cap 2 万，剩下的要么调大 cap 灌爆上下文、要么丢；
- 深度调研抓十几个页面 → 每页都要在"全塞"和"截断"之间二选一。

**同时**：hermes 明明已经有 `run_<shell>`（能跑 Python）、`grep_search`、`read_file`——**程序化处理数据的能力早就齐了**，缺的只是"数据落在磁盘上、有个稳定地址"。这正是 Prime Agent「Programmatic Context」思想里对 hermes 唯一真正缺失的那一块，而**不需要**引入它那套常驻 IPython 运行时（见「备选」）。

## 决策

**大工具输出落盘成「产物」，工具只回摘要 + 句柄；模型用已有的工具去处理产物。**

```
run_shell("pytest -q")
  → [产物 art_0007 · 417,203 字符 · 已存盘]
    [摘要] 前 60 行 + 后 40 行（中间省略 6,180 行）
    [提示] 完整内容在 <工作区>/.hermes/artifacts/art_0007.txt
           可以 grep_search 它、read_file 它（带 offset）、或写脚本聚合它
```

### 1. 产物是什么

一个产物 = **一个文件 + 一条元数据**。元数据存 JSON 台账（同技能安装台账的做法，放产物目录外）：

```json
{
  "id": "art_0007",
  "tool": "run_powershell",
  "params_digest": "a1b2c3d4",
  "created_at": 1786108443.2,
  "session_id": 12,
  "bytes": 417203,
  "lines": 6280,
  "content_type": "text/plain",
  "origin": "pytest -q"
}
```

### 2. 什么时候产物化（判据与范围）

**判据 = 「这次输出发生了截断/丢弃」且「原始量 ≥ `artifact_threshold`（默认 20,000 字符）」。**

判"有没有截断"、而不是判"输出够不够大"，是评审时改的（原草案是后者）。两个理由：

- **原判据在 `web_fetch` 上自相矛盾**：`WebConfig.fetch_max_chars` 默认**正好也是 20,000**，
  而它量的是**返回后**的长度——阈值取 20,000 则永远卡在边界上，取更大则它永远不落产物。
  真正该存的恰恰是**抓到了却被 cap 掉的原文**（46,000 字符的仓库页），所以判据必须量**原始数据**。
- **没截断的大输出存了也没用**：shell 回 30,000 字符（cap 是 200,000）时模型已经全看到了，
  再落一份磁盘副本是纯开销。

于是阈值降级成**防抖下限**（挡住 `max_chars=500` 这种小截断产生的碎片产物），不再是主开关。

首批接入三个：**前台 `run_<shell>`、后台进程输出（tee，见 §7）、`web_fetch`**。
不接：`grep_search` / `list_dir`（输出本就是"筛选结果"，再产物化是套娃）；
**`read_file` 评审时从首批移除**——源文件本身就在磁盘上、已经可寻址，`fs.py` 也早有 `offset/limit`
续读提示，产物化只是把文件复制一份，和排除 grep/list 的理由完全一致。

- **产物化 ≠ 不给内容**。工具仍然回一段**摘要**（头 + 尾 + 省略计数），保证模型不看产物也能继续干活；产物是"想深挖时的下钻入口"。
- **产物化 ≠ 不给内容**。工具仍然回一段**摘要**（头 + 尾 + 省略计数），保证模型不看产物也能继续干活；产物是"想深挖时的下钻入口"。

### 3. 摘要怎么给（纯逻辑，可单测）

`summarize_for_context(text, head_lines, tail_lines) -> str`：取头 N 行 + 尾 M 行，中间标 `…（省略 X 行，完整内容见 art_0007）`。
选头尾而非只取头：命令行输出的**结论通常在尾部**（失败汇总、退出码），只取头会把最有用的部分丢掉。

### 4. 模型怎么用产物

**不新增"读产物"的专用工具**。产物就是工作区里的普通文件，用现成的：

```
grep_search  pattern="FAILED" path=".hermes/artifacts/art_0007.txt"
read_file    path=".hermes/artifacts/art_0007.txt" offset=5200
run_shell    "python - <<'EOF' … 读 art_0007 聚合统计 … EOF"
```

这是本 ADR 的**核心取舍**：产物化只解决"数据可寻址"，处理数据复用既有工具链，**不造新抽象**。

### 5. 存哪、留多久

- 位置：`<工作区>/.hermes/artifacts/`（跟着工作区走，换项目即换产物集）；台账 `<工作区>/.hermes/artifacts.json`
  放在**产物目录外**（同技能安装台账的理由：不往内容目录里塞 sidecar）。
- 清理：**双上限**——产物总量上限（默认 200 MB）与保留天数（默认 7 天），超限按**最旧优先**删除；台账同步 prune（同技能台账"用户手删目录后自动 prune"的做法）。
- **不跨工作区共享**，不上传，不进打包。
- **不污染用户仓库**：首次建产物目录时自动写 `<工作区>/.hermes/.gitignore`（内容 `*`）**自我忽略**——
  绑定真实项目时 `.hermes/artifacts` 会冒进 `git_status` 和「改动」面板，自我忽略即可根治，
  且**不去改用户仓库根的 `.gitignore`**（那是用户的文件）。
- **不污染检索**：`tools/search.py` 的 `_SKIP_DIRS` 里没有 `.hermes`（`workspace.py`/`profile.py`/`verify.py`
  都已跳过，只漏了搜索这条），一个 40 万字符的 pytest 日志会污染此后**每一次全库 grep 和 BM25 索引**。
  改法要兼顾 §4 的核心用法（模型得能显式 grep 产物）：**默认跳过 `.hermes`，但当 `path` 显式指向
  `.hermes` 之内时不跳过**。

### 7. 后台进程：读线程 tee（唯一"重跑也拿不回来"的数据）

后台进程的环形缓冲（`procs.py` `MAX_BUF_CHARS=200_000`）是**读线程一边收一边丢最旧**，
所以**不能**沿用其它工具"返回时超阈值才落盘"的路子——等 `read_process_output` 被调用时早期输出早没了。

做法：**读线程 tee**——每个后台进程开一个 append-only 产物文件，读线程写环形缓冲的同时追加落盘；
**环形缓冲与 `read_process_output` 的增量语义一行不动**（零回归面）。代价是最多 8 个常开文件句柄
（`MAX_PROCS=8`）加追加写。这条是本 ADR 里唯一救"不可再生数据"的部分，优先级最高。

### 6. 与现有机制的关系

- **不动上下文压缩**（`context.py`）：产物化发生在工具返回时，压缩看到的已经是摘要。两者互补，且**绕开了 golden 门盖着的压缩内核**。
- **不动决策内核**（block A–E）：产物化是工具层的事，Need/Decision 映射不变，`test_golden.py` 无涉。
- **`recall_history` 仍是对话历史的无损兜底**；产物解决的是**工具输出**的无损保留，两者是不同的东西。
- `web_fetch` 的 `focus` 摘录（v3.53.0）是本机制的局部特例：产物化后 `focus` 变成"在产物上做的一次筛选"，两者可以共存。

## 影响

- 新增 `src/agentcore/artifacts.py`：`ArtifactStore`（落盘 + 台账 + prune，IO）与 `summarize_for_context()` / `should_artifact()`（纯逻辑，可单测）。
- `tools/base.py` 加一个可选的 `artifact_sink`，由 `build_registry` 注入给接入的工具——**同 `browser_reader` 的注入模式**，工具不自己管存储。
- 配置新增 `artifacts` 段：`enabled` / `threshold` / `max_total_mb` / `keep_days`。
- 前端：工具结果块里把句柄显示成可点的文件（复用工作区预览），让用户也能看全量输出——**顺带解决"用户看不到被截断内容"这个长期痛点**。
- 待验证项（Windows）：真机跑长命令后产物落盘、点句柄能在预览里打开、清理策略不误删当前会话产物。

## 风险与反对意见（自己先提）

1. **模型可能根本不去下钻**——只看摘要就下结论。缓解：摘要末尾明确写"完整内容在 X，需要细节请 grep/read"；真跑观察它会不会用（同 `focus` 那次——模型没被提示就自发用了，是个正面信号，但不能假定必然）。
2. **多一层间接会不会让简单任务变慢**：阈值 20,000 字符以下完全不触发，日常小输出零影响。
3. **磁盘占用**：双上限 + 最旧优先清理；默认 200 MB / 7 天。
4. **`.hermes/` 目录语义扩张**：现在已有 `.hermes/skills`，再加 `artifacts`。可接受，但要在 CLAUDE.md 里写清这个目录的约定。
5. **可能被当成"实现了 Prime 的 programmatic context"而放大宣传**——它不是。它只是让数据可寻址；真正的"模型写代码编排上下文"没做，也不打算做（见备选）。

## 备选（未采纳）

- **常驻 IPython/Python REPL 运行时**（Prime Agent 的做法）：把工具结果变成会话内变量、模型写代码操作。**不采纳**——hermes 已有 shell + 文件系统，程序化能力不缺；常驻解释器要处理状态生命周期、跨线程安全、崩溃恢复、与权限 gate 的关系，复杂度远超收益。**数据可寻址是 90% 的价值，常驻变量是剩下 10% 却带来 90% 的复杂度。**
- **只调大截断上限**：治标，且直接把上下文预算烧穿。
- **自动摘要（喂给小模型压缩）**：多一次模型调用、有信息损失、且不可回溯——产物化是无损的，且零额外模型成本。
- **专用 `read_artifact` 工具**：不必要——产物是普通文件，多一个工具就多一份模型要学的语义。

## 评审决议（2026-08-10，用户拍板）

| # | 问题 | 决议 |
|---|---|---|
| 1 | 产物跨会话可见吗 | **台账记 `session_id`，列表默认只列本会话；按 id / 路径读不设限。** 几乎不需要额外代码：默认 `per_session_workspace=true`，工作区就是 `data/workspaces/<session_id>/`，产物天然按会话隔离；只有用 📂 绑定真实项目文件夹时多会话才共享同一目录，此时列表末尾提示「本工作区另有 N 条历史产物」。越界由既有 `resolve_within` 兜，不再加一层会话校验（自造限制）。 |
| 2 | 后台环形缓冲是否同时落产物 | **要，且落盘时机改为读线程 tee**（见 §7）。原案"返回时落盘"救不了它。**本条优先级最高。** |
| 3 | 默认阈值 20,000 是否偏低 | **换判据，问题消解**（见 §2）：判「发生截断」而非「输出够大」，20,000 保留为防抖下限。 |
| 4 | （评审新增）`read_file` 要不要进首批 | **不进**——源文件本身已可寻址，产物化是套娃（见 §2）。 |
| 5 | （评审新增）`.hermes/` 的检索污染与 git 污染 | **两条都做**：搜索默认跳过 `.hermes`、显式指向时不跳过；产物目录自带 `.gitignore`（`*`）自我忽略（见 §5）。 |

## 落地分块

1. **块1**：`artifacts.py`（存储 + 台账 + prune + 纯逻辑摘要/判据）+ 配置段 + `.gitignore` 自我忽略 + 搜索跳过 `.hermes` + 单测。
2. **块2**：接前台 `run_<shell>` 与 `web_fetch`。
3. **块3**：后台进程读线程 tee。
4. **块4**：前端句柄可点开预览。
