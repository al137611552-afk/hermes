# 把程序变成技能

目标：让用户**下次只说人话**（"看看今天的动量排名"），你就知道该调哪条命令、输出怎么读、哪些话不能说。

**核心纪律：契约由你实测得出，不许猜。** 命令名、参数、字段含义，全部来自 `--help` 与**真跑一次的输出**。
猜出来的技能会让后续每一次调用都错，而且错得很隐蔽。

## 什么时候用

适用：用户手上有个能跑的程序（CLI / 脚本 / `python -m xxx`），希望以后用自然语言驱动它。
不适用：用户要的是**一次性执行**（直接跑就行，别建技能）；或那个"程序"其实还没写完（先帮他写完）。

## 流程

### 1. 先确认三件事（别跳过）

用 `ask_user` 一次问清，缺哪条问哪条：
1. **入口怎么调**：可执行名 / `python -m 模块` / 脚本路径；
2. **哪些是只读的**：接下来要真跑一条来取样，**只能挑只读命令**（查询、列表、`--help`），
   绝不碰会下单、写库、发消息、改远端状态的子命令；
3. **技能名**：全小写连字符（如 `futures-monitor`），也是目录名。

### 2. 摸接口

按这个顺序，能拿到就不必往下：
1. `<入口> --help`；子命令多的话再逐个 `<入口> <子命令> --help`；
2. 读源码里的参数定义（`argparse` / `click` / `commander` 等），用 `search_code` 找；
3. 都拿不到就问用户。

**把子命令与参数列成表**，这张表就是 SKILL.md 命令表的原料。

### 3. 真跑一条，拿真实输出（这步不能省）

挑一条**只读**命令实跑（优先加上 `--json` 之类的结构化输出开关）。
拿到的真实输出用来：
- 反推字段名、类型、单位；
- 判断输出规模（要不要默认加 `--top N` / 限制条数）；
- 发现"文档没写但实际有"的字段。

**跑失败也是信息**：缺依赖、要配置、要凭据——如实写进技能的「环境要求」，别假装不存在。

### 4. 写技能包

目录：`<工作区>/.hermes/skills/<技能名>/`（跟项目走）。至少两个文件：

```
<技能名>/
├── SKILL.md                  必需
└── references/OUTPUT.md      输出字段/单位/口径（字段多时单独放，正文只留摘要）
```

`SKILL.md` 的 frontmatter **只用规范字段**（`name` / `description` / `license` / `compatibility` / `metadata`），
别自造字段。正文按这个骨架写：

1. **什么时候用 / 不用**——`description` 里要含用户的**真实问法**（触发全靠它）；
2. **环境要求**——入口怎么调、要什么依赖或凭据（凭据只说"在 .env 里"，**绝不写值**）；
3. **命令表**——「用户问什么 → 跑哪条命令」，每行**可直接复制执行**，不留 `<TODO>`；
4. **输出字段**——名字、类型、单位、时点字段；字段多就放 `references/OUTPUT.md` 里；
5. **纪律**——见下节，按程序的性质挑。

### 5. 纪律怎么写（照抄这些，按需增删）

这些是"读懂输出"之外真正决定技能好坏的部分：

- **数值照抄，不改写、不换算、不外推**；需要工具没提供的口径就如实说"工具没给"。
- **数据时点/版本要报出来**（输出里有 `as_of`、时间戳、版本号就必须转述）；分不清"实时还是缓存"时明说。
- **命令失败或返回空，如实说**，附上工具原话。**把"数据源挂了"讲成"今天没有结果"是最严重的失败模式。**
- **多问题就多跑几条命令**，别猜、别把两件事合并成一条。
- 涉及钱、健康、法律、对外发送的程序：**只呈现数据，不给建议、不做预测**，并在技能里写死这条边界。

### 6. 自检（必须跑，改到过为止）

```
python3 <本技能目录>/scripts/check_skill.py <生成的技能目录>
```

它检查的是**能不能用**：frontmatter 合规、name 与目录名一致、description 有触发词、
命令表没留占位符、引用的文件真实存在、没把疑似密钥写进文件。退出码 0 通过 / 1 有问题必须修 / 2 用法错。

**自检不过就自己改到过**，别把问题留给用户。

### 7. 交付前问用户两件事

1. **要不要绑一个斜杠命令**？要的话写 `<工作区>/.hermes/commands/<命令名>.md`：
   ```markdown
   ---
   description: 一句话说明
   skill: <技能名>
   argument-hint: "[常用参数]"
   ---
   用 <技能名> 技能查 $ARGUMENTS。
   ```
   （命令名支持中文，`/盯盘` 可用；文件名即命令名。）
2. **常用的那条命令要不要免确认**？要的话告诉用户去 **设置 → ⌨ 命令**，在该命令行点「免确认」，
   或 **设置 → 🔐 权限** 手加一条更窄的规则。**你自己不要去改权限配置**——放行范围必须由用户明示。

最后把生成了什么、跑过哪条命令取样、自检结果，一次说清。

## 反面清单（做了就是没做好）

- 命令表里留 `<TODO>` 或"根据实际情况填写"——**等于把活推回给用户**；
- 没真跑过就写字段表；
- 把 API key、token 写进 SKILL.md 或 references；
- 替用户决定免确认范围；
- 为"以防万一"把非只读命令也写进命令表却不加警示。
